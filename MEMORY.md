## 1. Project Snapshot
MERN stack + Flutter mobile app.
- `frontend/` — React 18 + Vite + Tailwind (design tokens: `brand`/`accent`/`surface`/`ink` scales in `tailwind.config.js`). React Router. Axios to `API_BASE`.
- `server/` — Node/Express + Mongoose (MongoDB Atlas). JWT auth (`role: [admin|hr|employee|team_lead|candidate]`).
- `mobile/` — Flutter app (Dio + `theme/responsive.dart` helpers `context.w/h/sp`), mirrors employee-facing web features.
- Both `frontend/` and `mobile/` are surface pairs: an employee-facing change lands on both unless explicitly web-only (see CLAUDE.md §15).

## 4. Engineering Decisions
- **Attendance status thresholds**: <4h worked → `Absent`, 4–8h → `Half-Day`, ≥8h → `Present`/`Present + Overtime`. Same thresholds apply to Work-from-Home variants.
- **Check-in without check-out**: once the shift's calendar date (IST) has fully elapsed, status resolves to `Half-Day` instead of staying `Incomplete` forever. Computed *lazily* (string-compare the record's date against `toISTDateString(new Date())`) rather than via a nightly cron/reset job — no DB mutation needed. Implemented via `isPastDate()` in `server/controllers/attendanceController.js` (5 near-duplicate status blocks — a refactor opportunity) and mirrored in `frontend/src/components/EmployeeDashboard/AttendanceReport.jsx`.
- **Work Mode is mandatory** on the Attendance check-in screen (web + mobile): no default selection, Check In stays disabled until Office/Home is chosen, and the field locks (read-only) once checked in for the day.
- **"Attendance Corrections" (employee self-service regularization request) was removed** from both web and mobile — routes, sidebar/drawer links, and the components (`RegularizationRequest.jsx`, mobile `corrections_screen.dart`) were deleted. The **Team Lead / Admin "Attendance Approvals"** flow (`RegularizationApprovals.jsx` / mobile `ApprovalsScreen`) was intentionally kept — it's a different feature (approving requests, not submitting them) and is still wired up.
- **Logout** lives in each dashboard's sidebar footer (Admin/HR/Employee), not the shared top `Navbar` — moved so it isn't confused with the shared notification bell area.
- Employee `Employee.shiftId` (ref `Shift`) is populated in `getEmployee` (`server/controllers/employeeController.js`) so shift start/end can be shown where needed — currently **not** shown on the web Attendance page (removed per request); available if another surface wants it.
- **Mobile "Documents" feature removed entirely** (employee + admin) — deleted `documents_screen.dart`, `admin_documents_screen.dart`, `document_service.dart`, and their drawer entries. Do not re-add without checking this file.
- **Account deletion is request-based, not instant self-service** — appropriate because org Admin/HR provisions employee credentials (no self-signup). Full flow already exists: backend `AccountDeletionRequest` model + `accountDeletionController.js` mounted at `/api/account/deletion-request` (public/optional-auth) and `/api/account/deletion-requests` (admin/HR only) in `server/index.js`; public web page `frontend/src/pages/DeleteAccount.jsx`; mobile "Request Account Deletion" card + bottom sheet in `profile_screen.dart`. No admin-side review UI exists yet (deliberately not built — user said "no need for admin").
- **Firebase must stay on a single project across all four config sources**: `mobile/android/app/google-services.json`, `server/service-account.json`, `mobile/lib/firebase_options.dart` (Android + iOS blocks), and `mobile/ios/Runner/GoogleService-Info.plist`. Canonical project is **`new-hrms-d8eaf`** (project number `800902168034`). A prior mismatch (Dart-side `firebase_options.dart` pointed to an old `speshway-hrms` project while the native/backend configs pointed to `new-hrms-d8eaf`) would have silently broken FCM push delivery — fixed 2026-09-17; verify all four still agree before ever regenerating one of them via `flutterfire configure` or the Firebase console.
- **Mobile app-wide loading/error/empty states**: use `mobile/lib/widgets/skeleton_loader.dart` (shimmer skeletons: `SkeletonBox`/`SkeletonListTile`/`SkeletonCard`) and `mobile/lib/widgets/state_views.dart` (`NetworkErrorView`/`ErrorView`/`EmptyStateView` + `buildErrorState(error, retry)` helper, which branches on `isNetworkError()` in `api_client.dart`) — don't reintroduce ad-hoc `CircularProgressIndicator`/plain error `Text` on new screens.
- **Mobile caching**: `mobile/lib/services/data_cache.dart` provides a generic `DataCache<T>` + a `DataCaches` registry (attendanceToday, attendanceMonthly, leavesList, tasksList, payslipHistory, employeeProfile, events) wired via `MultiProvider` in `main.dart`, exposed through `AppCaches.of(context)`. Screens reached repeatedly via `Navigator.push` from Home should read from cache first (instant render) and silently refetch in the background (stale-while-revalidate) rather than showing a full skeleton on every revisit — already wired into Attendance, Attendance Report, Leaves, Tasks, Payslips, Profile, Calendar.
- **Mobile release signing is configured** (`android/key.properties` + upload keystore, gitignored on both `mobile/.gitignore` and `mobile/android/.gitignore`) — `flutter build appbundle --release` produces a real release-signed AAB. Do not touch signing config/keystore without explicit approval (per playstore.md §40).

- **`mobile/test/`** now has a real suite (17 tests: `models/user_test.dart`, `services/api_client_test.dart`, `widgets/status_pill_test.dart`) — `flutter test` previously errored with "Test directory not found" since the folder didn't exist at all. ## 11. Do Not Repeat
- Don't add a nightly cron to "reset"/finalize attendance at midnight — the lazy `isPastDate()` comparison achieves the same displayed result without extra scheduled jobs or DB writes.
- Don't re-add "Attendance Corrections" self-service without checking this file first — it was deliberately removed on both web and mobile.
- Don't re-add the mobile "Documents" feature without checking this file first — deliberately removed.
- Don't regenerate only one Firebase config file (e.g. just `firebase_options.dart` via `flutterfire configure`) without also verifying `google-services.json`, `service-account.json`, and `GoogleService-Info.plist` still agree — this exact mismatch already caused a silent push-notification bug once.
- Don't bump Gradle/AGP/Kotlin versions opportunistically "while in there" — it's a deliberate, isolated decision (see Current Work) given the risk to the now-verified release build.

- **Mobile login screen** (`login_screen.dart`) wraps the brand header (logo/title/tagline) in a fixed-width `SizedBox(280)` + `FittedBox(fit: BoxFit.scaleDown)` inside its top `Expanded` region — required because that region can shrink below the header's natural content height when the on-screen keyboard opens, which previously caused a real bottom-overflow render error. Don't remove the `FittedBox`/`SizedBox` wrapper without re-testing with the keyboard open on a short-height device.
- **Mobile splash screen has no spinner** (`splash_screen.dart`) — removed per explicit request; only the fade+scale logo/wordmark shows during the `_bootstrap()` session-restore delay. Don't re-add a loading indicator here without checking first.
- **Mobile state screens** (`mobile/lib/widgets/state_views.dart`) are the canonical illustrated full-page states: `NetworkErrorView`, `ErrorView`, `EmptyStateView`, and `SuccessView` (all use the shared `_StateScaffold` — layered soft-circle icon badge + scale/fade entrance). Use `buildErrorState(error, retry)` at call sites rather than picking Network/Error manually. Don't build one-off inline error/empty widgets on new screens — use these.
- **Physical Android device testing needs an explicit LAN API URL**: `10.0.2.2:5001` (the dev default) only works on the Android **emulator**. For a real phone, run `flutter run --dart-define=API_BASE_URL=http://<PC-LAN-IP>:5001` with phone + PC on the same Wi-Fi (this machine's LAN IP as of 2026-09-18: `192.168.1.17` — re-check with `ipconfig` if it changes). If it still can't connect, check Windows Firewall isn't blocking inbound port 5001.
- **Login screen network-error handling**: `AuthProvider.lastErrorRaw` holds the raw caught exception (not just the stringified `lastError`) specifically so `login_screen.dart` can call `isNetworkError()` on it and show the illustrated `NetworkErrorView` instead of a generic snackbar for connectivity failures. The login `Form` is kept mounted via `Offstage` (never removed from the tree) while that view shows, so `_formKey` stays valid for a Retry resubmit — don't swap the form out with an `if/else` (that null-checks `_formKey.currentState` on retry).
- **`GeneratePayslipByDays.jsx` (web, admin-only "Generate Payslip for Custom Days") — final design (superseded two earlier attempts, don't re-litigate without re-reading this).** Basic/DA/HRA/Conveyance/Medical/Special always show full, unprorated template values. LOP Days = 0, LOP Amount = 0, Other Deductions = 0 (Total Deductions displayed = PF + Prof Tax only) — all match a full-month payslip exactly. Only **Net Pay** reflects days actually worked, via an explicit `netPayOverride` field: `max(0, (fullGrossEarnings × daysWorked ÷ calendarDaysInMonth) − (pf + proftax))`. This is necessary because `Net Pay = Total Earnings − Total Deductions` (used everywhere else in the codebase) cannot produce a reduced Net Pay while Earnings/Deductions both stay at full/fixed display values — there is no other way to reconcile "show full figures" with "genuinely cut pay" than an explicit override consumed downstream. Wired through: `server/controllers/payslipController.js` (`generatePayslip` + `previewPayslip`, both fall back to the old `totalEarnings − totalDeductions` when no override is sent — zero impact on `PayslipGenerator.jsx`'s normal flow), `server/utils/pdfGenerator.js`, `frontend/.../PayslipPreview.jsx`, and `frontend/.../View.jsx` (payslip history detail) — all four now prefer the stored/passed `netSalary` over recomputing it locally. Mobile (`payslips_screen.dart`) already read `netSalary` directly and needed no change. **Two earlier, now-abandoned designs**: (1) prorate every earnings line item, force LOP Days/Amount to 0 — self-consistent but hid the real cut from view; (2) show full earnings, put the cut in a visible "LOSS OF PAY" line — technically correct but not what the user wanted once compared against their actual reference payslip. Don't revert to either without checking with the user first.
- `PRABHUSWAMY M_AUG.pdf` (referenced repeatedly during payslip work): **not actually buggy — an earlier read of this file was wrong.** It looks arithmetically broken if you assume `Net Pay = Total Earnings − Total Deductions` (40000 − 3800 = 36200 ≠ its printed 22006.45), but it's correct under the `netPayOverride` formula documented above: `(40000 × 20 ÷ 31) − 3800 = 22006.45` — exact match. This is the reference this whole payslip-by-days feature was designed to reproduce; don't dismiss it as a "stale artifact" again.

- **Mobile web viewport is locked** (`frontend/index.html`): `maximum-scale=1.0, user-scalable=no` — pinch-zoom is intentionally disabled per explicit, repeated user request. Combined with global CSS in `frontend/src/index.css` (`html, body, #root { overflow-x: hidden; max-width: 100% }` and a 16px floor on `input`/`select`/`textarea` font-size under 768px, which stops iOS Safari's auto-zoom-on-focus). Don't remove these without confirming the user still wants zoom disabled — this trades away some accessibility (WCAG 1.4.4 reflow/zoom) for a "never accidentally zooms" experience, which was an explicit, informed choice.
- **Dashboard sidebar open-state must be viewport-aware**: `EmployeeDashboard.jsx`/`AdminDashboard.jsx`/`HRDashboard.jsx` initialize `sidebarOpen` from `window.innerWidth >= 768`, not a hardcoded `true` — a hardcoded default previously caused the sidebar to cover the whole screen on mobile on first load.
- **Employee web dashboard has a mobile bottom nav** (`frontend/src/components/EmployeeDashboard/MobileBottomNav.jsx`, `md:hidden`, wired into `EmployeeDashboard.jsx`): 5 tabs (Leaves/Attendance/Home/Tasks/Profile) mirroring the Flutter app's bottom bar. The sidebar/hamburger is still there for everything else — same pairing the mobile app itself uses (bottom tabs + drawer). Don't remove the sidebar thinking the bottom nav replaces it — it's additive, for parity with the mobile app's exact navigation pattern.
- **Payslip preview/history modals (`PayslipPreview.jsx`, `View.jsx`) must stack to 1 column below `sm`** — they intentionally mimic a printable A4 document (2–4 column grids, fixed-ish pixel spacing) which is fine on desktop but was unreadable on mobile before an explicit `sm:` breakpoint was added to every grid/flex split. If either file is regenerated or "restored to match the PDF exactly," re-verify the responsive breakpoints weren't dropped again.

- **Admin web dashboard also has a mobile bottom nav** (`frontend/src/components/dashboard/AdminMobileBottomNav.jsx`, `md:hidden`, wired into `AdminDashboard.jsx`): Leaves/Home/Employees/Settings, mirroring the Flutter app's admin tabs. Same additive pairing as the employee one — sidebar stays for everything else.
- **Any list using `react-data-table-component` needs an explicit `sm:hidden` mobile card list** — the library's own `responsive` prop and column `omit` are not enough to make it usable on narrow screens (confirmed broken in `PayrollTemplateManager.jsx`). Follow the pattern in `TaskList.jsx`/`TeamList.jsx`/`PayrollTemplateManager.jsx`: `hidden sm:block` wrapping the `DataTable`, plus a hand-built `sm:hidden` card list next to it. Check other `DataTable` usages (`AnnouncementList.jsx`, `employee/List.jsx`, etc.) if a similar mobile complaint comes up there.
